# 音频设计：为「轮回命书」配乐与音效

> **⚠️ 现状（2026-11-15 晚）：背景音乐已全部移除。**
> 实测听感上，低音持续层（drone）与和声垫在长时间游玩中过于压迫，用户决定
> 只保留音效。`engine.ts` / `score.ts` / `theory.ts` 已删除，音频模块现在只负责
> 事件音效（19 个）与多人远钟。
>
> 本文档保留为设计记录 —— 第三到五节描述的调式与分层系统已不在游戏里运行；
> 第六节（音效设计）与第七节（混音）仍然是现存实现的依据。
> `audio-preview.html` 也保留为设计原型，游戏里不再加载。

给一个一局要跑 1000 年以上、八成玩家停在凡人段的文字游戏做声音。

结论先说：**不做音频文件，做音频引擎**。全部用 Web Audio 现场合成，不用 mp3/ogg，也不用 Stable Audio / ACE-Step 渲染的成品。理由在第一节，后面是完整设计。

---

## 一、先算清楚约束，再谈好不好听

这些数字决定了架构，不是审美偏好。

### 1.1 一局到底多长

按 `packages/data/src/cultivation/realms.ts` 的门槛与 `annualGain` 的 1.0–1.6 倍加成区间估算：

| 阶段 | 小阶段 × 门槛 | 每年修为 | 停留年数 |
|------|---------------|----------|----------|
| 凡人 | 年龄 0–100 | — | 100 |
| 炼气 | 9 × 200 | 9–14.4 | 125–200 |
| 筑基 | 4 × 340 | 12–19.2 | 71–113 |
| 金丹 | 4 × 480 | 15–24 | 80–128 |
| 元婴 | 4 × 640 | 18–28.8 | 89–142 |
| 化神 | 4 × 800 | 21–33.6 | 95–152 |
| 炼虚 | 4 × 1000 | 24–38.4 | 104–167 |
| 合体 | 4 × 1200 | 27–43.2 | 111–178 |
| 大乘 | 4 × 1450 | 30–48 | 121–193 |
| 渡劫 | 9 劫 × 90 准备度 | 6/年 | 135 |

**活到飞升 = 1030–1508 岁。** 自动模式 `AutoInterval = 500ms`，一局连续播放 **35–50 分钟**。

### 1.2 但八成玩家根本走不到修仙

按 `core` 的 5000 局模拟（见 `2026-11-15.md`）：

- 寿命中位 **74 岁**
- **79% 的局活不到 100 岁**，永远停在凡人段
- 只有 **7.8%** 入道
- 只有 **0.56%** 飞升

这不是"修仙游戏附带凡人序章"，是**凡人人生游戏，少数人偶然推开仙门**。

### 1.3 所以

| 结论 | 依据 |
|------|------|
| 凡人段音乐必须自己撑满一整局，不能当"等待室" | 79% 的玩家只听得到它 |
| 修仙段音乐篇幅要极长且不重复 | 单境界停留 70–200 年 |
| 必须程序生成，不能用固定音轨 | 35–50 分钟连续播放，30 秒循环会变成酷刑 |
| 高潮不能靠"更响"，要靠"更静" | 长时段听觉疲劳 |
| 高境界可以做得更极端 | 不到 1% 的人听得到，不必讨好大众 |

顺带一个好处：零音频资产意味着零加载、零版权风险、零包体积，也符合项目"不引入大型游戏引擎"的既有约定。

## 二、三层驱动

音乐不是一条播放列表，是**状态的一个函数**。

```
        ┌─ 场景层   Step: Home/Pick/Alloc/Play/Summary ── 决定"在哪"
驱动源 ─┼─ 境界层   state.cultivation.realm (0–9)      ── 决定"是什么"
        └─ 年份层   state.props.current.age            ── 决定"走到哪"
```

- **场景层**：换曲只发生在页面切换，交叉淡入 1.2 秒。
- **境界层**：纵向增删音轨（vertical remixing），不换曲，只叠/减。
- **年份层**：凡人段每十岁一次微变奏；修仙段每个小境界换一次旋律种子。

三层都是纯数据查询，没有动画、没有定时器逻辑，好测也好调。

## 三、凡人段：十年一章

这一段的情绪不是"仙气"，是**人间烟火 + 一点荒诞**。游戏标语是"这垃圾人生一秒也不想待了"，配乐如果煽情就跑偏了。

`LogList.tsx` 里已经有整十岁的章节分隔（十岁·启蒙、二十·及冠……百岁·期颐），音乐直接挂同一个边界，**视觉与听觉同时翻页**。

| 年龄 | 章节 | 音色与织体 | 意图 |
|------|------|-----------|------|
| 0–9 | 启蒙 | 高音八音盒，单声部，稀疏 | 好奇、空白 |
| 10–19 | 及冠 | 加入低音与弱拍 | 开始有推力 |
| 20–39 | 而立/不惑 | 三声部稳定，节奏成形 | 生活运转起来 |
| 40–59 | 知天命 | 和声加厚，**首次借用 bVI** | 一丝不属于人间的裂缝 |
| 60–79 | 花甲/古稀 | 旋律降八度，密度减半 | 衰老，不是悲情 |
| 80–99 | 耄耋/鲐背 | 单音 + 长混响，接近静默 | 只剩骨架 |
| 100 | 期颐 | **磬声**，其余全停 | 入道 |

三点设计取舍：

**八音盒刻意微走音。** 每个音随机 detune ±8 cent，音准不完美。听感像旧电视里的音乐盒——熟悉、略假、有点好笑。这是全曲唯一"不准"的地方，正好对应凡人段的荒诞基调。

**bVI 是伏笔。** 自然大调里借用降六级（相对宫音的小六度），会瞬间产生"不属于这里"的色彩。只在 40 岁后偶尔出现一次，不解释、不解决。玩家不会注意到，但入道那一刻的调式切换会因此显得"一直就该来"。

**80 岁后接近静默。** 大多数玩家在 74 岁结束，最后听到的是越来越薄的声音。不煽情，但诚实。

## 四、修仙段：境界是纵向，小境界是横向

### 4.1 调式：旋宫转调

全程五声音阶（宫商角徵羽），但**每个境界把"宫"挪到不同的音上**。这样音高材料始终是五声，仙气不散；而调式重心变化，带来"越走越远"的感觉。

| 境界 | 调式 | 相对主音的音程 | 性格 |
|------|------|----------------|------|
| 炼气 | 宫 | 0 2 4 7 9 | 稳、亮、正 |
| 筑基 | 宫→徵 | 0 2 5 7 9 | 暖、有力 |
| 金丹 | 徵 | 0 2 5 7 9 | 明亮、confirmed |
| 元婴 | 徵→羽 | 0 3 5 7 10 | 转阴、出窍 |
| 化神 | 羽 | 0 3 5 7 10 | 冷、远 |
| 炼虚 | 羽（低八度） | 0 3 5 7 10 | 空 |
| 合体 | 羽→宫 | 0 2 4 7 9 | 归一、回归 |
| 大乘 | 宫（高八度） | 0 2 4 7 9 | 庄严、顶点 |
| 渡劫 | 角 + 借 b2 | 0 3 5 7 10 + 1 | 不解决、撕裂 |
| 飞升 | 宫（超八度） | 0 2 4 7 9 | 一次性 |

调式走向是**升—远—空—归—顶**，一条完整的拱形，不是单调爬升。这是 1000 年不腻的结构保证。

### 4.2 纵向：境界决定有哪些层

| 层 | 内容 | 凡人 | 炼气 | 筑基 | 金丹 | 元婴 | 化神 | 炼虚 | 合体 | 大乘 | 渡劫 |
|----|------|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| L0 | 纸声底噪 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| L1 | 持续低音 | – | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| L2 | 主旋律 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | **–** | ✓ | ✓ | ✓ |
| L3 | 和声垫 | – | – | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| L4 | 节拍 | – | – | – | ✓ | ✓ | – | – | – | ✓ | ✓ |
| L5 | 磬/铃 | – | 稀 | 稀 | – | ✓ | ✓ | ✓ | ✓ | ✓ | – |

两个刻意的选择：

**炼虚没有主旋律。** 只剩低音、和声与磬。境界越高越"虚"，这里直接虚到没有旋律线。很少人听得到，但听到的人会记住。

**化神撤掉节拍。** L4 在化神消失，时间感变模糊——神念覆盖天地之后，心跳就不重要了。到大乘再回来，且是重鼓。

### 4.3 横向：小境界换种子

同一境界停留 70–200 年，光靠纵向分层不够。`state.cultivation.minor` 提供第二个维度：

- **旋律种子 = hash(realm, minor)**。四个小阶段四个种子，同境界内不重复。
- **炼气特殊**：有九个层，把 minor 0–8 直接映射到五声音阶的第 0–8 级（跨两个八度）。**炼气一层到九层，旋律基准音高真的在往上爬。** 玩家不会说清哪里变了，但会觉得"在往上走"。
- 每过一个小境界，增加一个装饰音型（倚音/滑音/泛音），只加不换。

### 4.4 旋律生成

不用预写旋律，用带约束的随机游走：

```
从主音开始
每步：70% 级进（±1 级），25% 跳三/四度，5% 停留
乐句 8 小节，句尾必须落 宫 或 徵（稳定）
每第 4 句改为落 羽（开放、悬置）
每句 12% 概率整句休止 —— 留白比加音符重要
```

节奏型随境界变化：凡人段用附点（不稳），修仙段改用均分（定），渡劫改用切分（乱）。

## 五、渡劫与飞升

这两个是全局最重要的两个声音，必须单独设计。

### 5.1 渡劫：135 年，九次心跳

- 基础 72 BPM，**每过一劫 +3 BPM**（72→99），135 年慢慢加速。
- 低频大鼓落 1、3 拍，音高 55Hz。
- 加入一个非五声的 **b2（小二度）**，与其他音始终不解决。这是"天劫"的音响符号——五声里本来没有这个音，它的存在本身就是异质。
- 每次冲击雷劫：**先全部静音 400ms，再落雷**。雷前的空白比雷本身更吓人。
- 雷后 1.5 秒只留混响尾巴（对应引擎里的"雷隙"）。

### 5.2 飞升：一次，12 秒

结构是 **静 → 击 → 升 → 散**：

| 时间 | 事件 |
|------|------|
| 0.0s | 全曲硬切，真静音 600ms |
| 0.6s | 磬单击（F5），长衰减 |
| 1.4s | 五声从低到高逐音堆叠，5 秒爬升 |
| 6.4s | 全奏重击 + 压缩器释放 |
| 7.0s | 只留 8 秒混响尾，逐渐消失 |

关键是开头那 600ms 的**绝对静音**。整局游戏一直有底噪，突然什么都没有，玩家的耳朵会自己"竖起来"。这一下比任何音效都贵。

## 六、音效：直接挂在现成的语义总线上

`apps/web/src/fx/rare.ts` 已经把每个游戏时刻分类成了 `tier` + `tone` + `tag`，而且有幂等 key。**音效不需要另写一套判定**，直接复用：

| 来源 | tone / tag | 音效设计 | 长度 |
|------|-----------|----------|------|
| 年度流逝 | — | 木质轻叩，极轻（可关） | 40ms |
| 抽卡翻牌 | — | 纸/竹签翻动：噪声 + 带通 | 80ms |
| 橙色天赋 | gold | 磬 + 五度叠加 | 1.2s |
| 灵根玉简 | gold / 稀有天赋 | 玉片相击：高频 FM + 长衰减 | 1.6s |
| 天赋链替换 | — | 下行 + 上行两段 | 0.8s |
| 属性变化 | — | 极短正弦上/下滑 | 60ms |
| 大境界突破 | tier2 | 鼓 + 磬 + 上扬扫频 | 1.8s |
| 雷劫 | azure | 低频轰 + 高频碎裂噪声 | 2.4s |
| 顿悟 | jade | 泛音列钟声，五度堆叠 | 2.6s |
| 天兆 | azure | 单音 + 长混响 | 2.0s |
| **魔修偷袭** | blood / 魔劫 | 刀光：噪声扫频下坠 + 低频撞击 + 心跳 | 2.2s |
| 飞升 | gold / tier3 | 见 5.2 | 12s |
| 身死道消 | blood / 结局 | 单音下沉 + 混响吞没 | 3s |
| 转世重修 | jade / 结局 | 倒放式上扬 + 心跳重启 | 2.4s |
| 印章落下（结算页） | — | 闷响 + 纸摩擦 | 300ms |

**tone 决定音色家族**，这是整套音效的秩序来源：

- `gold` → 金属（FM 钟、磬、铃）
- `violet` → 弦（拨弦、短促）
- `azure` → 噪声（滤波扫频、雷、水）
- `jade` → 木石（带通噪声、木质共鸣）
- `blood` → 低频冲击 + 噪声撕裂

同 tone 的音效共享同一个合成器参数族，所以听起来"是一家的"，不用逐个调 EQ。

## 七、混音

```
每个音源 → 各自 gain → ┬ musicBus (0.22) ─┐
                       └ sfxBus   (0.50) ─┴→ master (0.85) → Compressor → destination
```

- **Compressor**：threshold −12dB、ratio 4、release 250ms。项目里没有母带流程，这个用来兜住 tier3 音效叠加时的爆音。（参考：`~/AI/music/comparisons/REPORT.md` 里 SA3 的 45 秒片段有 2865 个削波采样点，就是没做这一步。）
- **闪避（ducking）**：tier3 音效触发时，musicBus 在 200ms 内降到 −18dB，1.2 秒恢复。保证魔劫/飞升不被音乐盖住。
- **并发上限 16 个发声单元**，超出丢最旧的。自动模式下一局每秒约 2 个事件，不设上限会在长局里累积。

## 八、多人

`Battle.tsx` 同屏五列，每人每年都推进。如果五个人的事件都发声，就是噪音。

规则：

- **只有自己那一列触发音效**（现有 `emitRareFxFromNext` 已经只对本地下一次调用）。
- **对手只播两种音**：死亡、飞升。用远处的钟声，音量 −24dB，按列序左右声像（player 0 左 → player 4 右）。你会"听见"有人死了，但不被打断。
- **排行榜易主**：一声极轻的铃，仅此。

多人共用的房间大厅（`Room`）用一条更安静的循环，和单人 `Play` 区分开。

## 九、无障碍与用户习惯

项目已有 `prefers-reduced-motion` 支持，音频侧对应做：

- **默认音量保守**：music 0.22、sfx 0.50。
- **持久化**：`localStorage.audio = { music, sfx, muted }`，与 `theme` 同套路（`ThemeToggle.tsx` 已有先例）。
- **必须用户手势解锁**：`AudioContext` 在首页「立即重开」点击时创建。浏览器本来也会拦，正好利用这个交互。
- **切后台挂起**：`visibilitychange` 隐藏时 `ctx.suspend()`，回来 `resume()`。一局 50 分钟，不能让它后台空转。
- **年度流逝音默认关**。一年一声在 1000 年的尺度上会烦，给个"书页声"开关，爱开的人自己开。
- 一个喇叭图标放在 `Home` 的 `.actions` 和 `Play` 的标题栏，点一下静音，不弹面板。

## 十、技术实现

### 10.1 文件结构

```
apps/web/src/audio/
  context.ts     AudioContext 单例、master/compressor、挂起恢复
  theory.ts      五声/旋宫数学，音级 → Hz，种子哈希
  synth.ts       合成原语：pluck / bell / pad / drum / noise
  reverb.ts      程序生成 IR（噪声衰减）→ ConvolverNode
  score.ts       境界/年龄 → 层配置表（纯数据，无副作用）
  engine.ts      前瞻调度器、层增删、交叉淡入
  sfx.ts         具名一次性音效注册表
  bridge.ts      订阅 rare.ts 与 stepAtom → 分发到 engine / sfx
  settings.ts    音量与静音持久化
  index.ts
```

`Game.tsx` 里挂一个 `<AudioRoot />`，与 `<RareFxLayer />` 并列。`subscribeRareFx` 用的是 `Set<Listener>`，天然支持多订阅者，不需要改 `rare.ts`。

### 10.2 调度器

标准前瞻模式，不能用 `setTimeout` 直接排音（会漂）：

```ts
// 每 25ms 检查一次，把未来 120ms 内的音符排进 ctx 时间轴
const LOOKAHEAD_MS = 25
const SCHEDULE_AHEAD = 0.12
```

所有音符时间都基于 `ctx.currentTime`，节拍位置用一个单调递增的 `nextNoteTime` 累加，与页面帧率完全解耦。切后台时不排音，回来重新对齐，不做补播。

### 10.3 合成原语

不引第三方库，四个振荡器型够用：

| 原语 | 做法 |
|------|------|
| `pluck`（琴/筝） | 三角波 + 低通（截止从 4kHz 衰到 400Hz，80ms）+ 指数包络 |
| `bell`（磬/钟） | FM：载波正弦，调制比 3.5，调制指数从 8 衰到 0.1，衰减 4–8s |
| `pad`（和声垫） | 三个正弦（根/五度/八度）各 ±3 cent 失谐，2.4s 起音 |
| `drum`（鼓/木鱼） | 预生成噪声 buffer → 带通 → 快衰减；大鼓用 55Hz 正弦下滑 |

混响不用外部 IR 文件：生成 1.8 秒白噪声，施加 `exp(-t/0.45)` 衰减，做成立体声 buffer 喂 `ConvolverNode`。听感够用，零资产。

### 10.4 性能

- 单个音符最多 3 个节点（osc + gain + filter），16 并发 = 48 节点，M 系列芯片毫无压力。
- 噪声 buffer 全局复用一个。
- `score.ts` 是纯查表，不产生对象。
- 合成器参数全部用 `setTargetAtTime`，避免 `linearRamp` 造成的 zipper noise。

## 十一、和那两个 AI 模型的分工

`~/AI` 里的 SA3 和 ACE-Step 我实测过（SA3 出 12 秒音频 1.45 秒，8.26× 实时；ACE-Step 支持中文歌词但冷启动 80 秒）。它们在这儿只有一个合理位置：

**玩家停留时间短的地方，用渲染好的成品；停留长的地方，必须程序生成。**

| 场景 | 停留时长 | 方案 |
|------|----------|------|
| Home 标题页 | 10–60 秒 | **可以用 ACE-Step 做一首 45–60 秒主题曲**。旋律记忆点需要"固定"才能建立，程序生成反而记不住。 |
| Pick / Alloc | 30 秒–2 分钟 | 程序生成（短，但要和境界无关的独立氛围） |
| **Play** | **35–50 分钟** | **必须程序生成**，固定音轨必死 |
| Summary | 10–30 秒 | 可以渲染一首短结局曲，按结局类型分五版 |
| 音效 | — | 全部程序合成，短音效合成比生成模型更精确可控 |

所以推荐是**混合，但代码优先**：先把引擎做出来覆盖 95% 的时长，标题曲和结局曲如果之后觉得不够，再拿 ACE-Step 补两首固定曲。这也符合你说的"工具只是参考"。

## 十二、落地顺序

按"投入产出比 × 玩家覆盖率"排，不是按代码顺序：

| 阶段 | 内容 | 覆盖 | 工作量 |
|------|------|------|--------|
| **1** | 凡人段完整（十年一章 + 入道转折）+ 6 个核心音效 | **79%** | 中 |
| **2** | 修仙段纵向分层（炼气→大乘）+ 渡劫 | 8% | 中 |
| **3** | 飞升、结局、转世三套终局音 | 1% | 小 |
| **4** | 多人（对手死亡/飞升远钟、排行榜铃） | — | 小 |
| **5** | 标题曲 / 结局曲（可选，用 ACE-Step） | — | 小 |

**第 1 阶段做完，八成玩家听到的就是完整的一套。** 这是我建议的第一个里程碑，也是唯一必须做对的部分——如果凡人段不好听，后面做得再仙也没人听得到。

## 落地情况

### 最终形态：只留音效

背景音乐整套移除后，`apps/web/src/audio/` 剩五个文件：

| 文件 | 职责 |
|------|------|
| `synth.ts` | 拨弦 / 钟磬 / 鼓 / 噪声四个原语 + MIDI 转频率 |
| `context.ts` | 音频图（单条音效总线 + 混响支路）、解锁、挂起 |
| `sfx.ts` | 19 个具名音效 + rare 语义映射 |
| `settings.ts` | 音效音量与总开关的持久化 |
| `bridge.tsx` | React 接缝（`AudioRoot` / `AudioToggle`） |

接进游戏的位置五处：`Game.tsx` 挂 `AudioRoot`，首页与对局页各一颗喇叭，
抽卡翻牌、属性跨档、结算落印三个交互各加一行音效。

移除的东西：`engine.ts`（前瞻调度器、境界分层）、`score.ts`（境界/年龄 → 音乐参数）、
`theory.ts`（五声与旋宫数学），以及 `context.ts` 里的 `musicBus` 与 `duck` 闪避节点。
`settings` 里的 `music` 字段一并去掉。

### 为什么删

低音持续层（L1）与和声垫（L3）是设计里"让静音不空"的底噪，但它们**一直在响**，
在长时间游玩中变成了压迫感而不是氛围。音效是一次性的、跟事件绑定的，
不会被听成噪音；背景音乐是持续的，只要玩家觉得不对，再好的调式设计也没用。

留下的判断标准很简单：**只在有事发生时出声，没事的时候是安静的。**

### 实测数据（移除后重测）

- 实时上下文 `state=running`，时钟 0.01→0.88 正常推进
- 19 个音效全部执行无异常，`errors=0`
- 图形状确认：`hasMusicBus=false`、`hasDuck=false`
- 离线渲染真实合成模块：峰值 −9.0 dBFS，RMS −29.5 dBFS，无削波
- `apps/web` 的 `tsc --noEmit` 通过

### 与最初设计稿的差异

- **背景音乐没有落地**，见上。第三到五节的调式与分层设计保留为记录。
- **年度流逝音始终没做**。一千年的尺度上，每年一声只会变成噪音。
- **多人对手的声像做了**（`bell()` 的 `pan` 参数），按五列从左到右摆位。
