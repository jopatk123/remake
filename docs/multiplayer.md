# 多人对战模式

在原版单人流程之外加的一条并行链路：几个人通过房间链接加入同一局，**每年自动同步推进**，比谁走得远。
对战过程中所有人的一生**并排显示在同一块屏幕上** —— 不是只看别人的年龄数字，而是能看到他现在经历了什么。

单人流程完全不受影响 —— 不连房间时 `Play` 仍然走原来的 `next()` 直连。

## 一、架构：中继 + 各自计算（方案 B）

服务端**不跑游戏逻辑**，不知道事件内容，只负责两件事：房间成员关系、以及"什么时候一起过一年"。

```
浏览器 A ──┐                   ┌── 浏览器 A：本地 next() 推进一年，sync 属性 + 日志
           ├── ws 中继（房间）──┤
浏览器 B ──┘                   └── 浏览器 B：本地 next() 推进一年，sync 属性 + 日志
```

这么选的原因：

- `packages/core` 是纯函数（`next(state, profile)`），零 DOM 依赖，两边可以共用同一份规则代码
- 每个人的状态彼此独立，没有共享世界状态，不需要做状态同步/冲突消解
- 推进是离散的"一年一步"，天然适合锁步节拍，不需要高频广播

代价是没有防作弊：客户端改代码就能刷年龄。朋友之间玩可以接受；将来要做公开匹配或排行榜，再把 `core` 搬到服务端升级成方案 A（服务端权威），**协议不用改**。

## 二、协议

类型定义在 `packages/multi/src/protocol.ts`，前后端共用同一份。

| 方向 | 消息 | 说明 |
|---|---|---|
| C→S | `join { room, name }` | 加入房间，服务端回 `welcome { id }` |
| C→S | `start` | 只有房主能用，**随时可以开始**，不要求别人准备 |
| C→S | `pause { on }` | 任意玩家都能暂停 / 继续，服务端只认最后一条 |
| C→S | `speed { ms }` | **任意玩家**都能调节拍，服务端夹到 `[200, 5000]` 毫秒 |
| C→S | `sync { age, life, alive, summary, props, logs }` | 每年推进后上报自己的状态快照；第一条 sync 也算"我进入对局了" |
| C→S | `danmaku { text }` | 发弹幕，服务端净化 / 截断 / 限流后广播 |
| S→C | `room { room }` | 房间全量视图（含 `round / interval / paused / pausedBy / waiting / result`）；结算也走这条，`result` 是上一局排名 |
| S→C | `tick { round }` | 服务端节拍：该一起过下一年了 |
| S→C | `danmaku { id, from, name, text, at }` | 弹幕广播，发的人也收到一份 |
| S→C | `error { message }` | 提示信息 |

**没有 `ready`/`cancel` 了。** 推进不靠"举手凑齐"，而靠服务端定时发 `tick`（默认 1.5 秒一拍，`ROUND_MS` 环境变量可调）。这样谁都不用点，也不会因为一个人挂机把整局卡住 —— 想停下来看文字就 `pause`，嫌快嫌慢就 `speed`。

### 日志为什么只传 id

`logs` 里每一年是 `{ age, events, talents, achievements }`，全是数据表 id，不传文本。文本在本地 `@remake/data` 里按 id 查表渲染，好处有三个：

- 传输量小一个数量级（8 人 × 80 年全程约几十 KB）
- 同一年在所有人屏幕上长得完全一样，不会出现"你那显示有事、我这没显示"
- 服务端不需要理解内容，仍然是纯中继

每人只留最近 `LOG_LIMIT`（18）年，足够填满一屏；更早的滚出去就没了。

## 三、房间与邀请

- 房间号是 4 位（去掉易混淆的 `I/O/0/1`），进房页默认随机生成一个
- 邀请方式是**链接分享**：`https://<域名>/?room=ABCD`
- **链接打开就直接进房间**：`Game.tsx` 在首帧检查 `?room=`，有值就跳过首页直接渲染房间页；本机存过昵称的话连"加入房间"都不用点，自动入房
- 第一个加入的人是房主；房主随时可以开始对局，**不必等任何人准备**，一个人也能开（方便自己先跑一局试试）
- **房主掉线 / 离开会自动换人**：在还没掉线的人里**随机**挑一个接班，开局中和房间里都生效 —— 否则房主一断线，下一局就没人能按开始了
- 上限 8 人；**开局后不再接受新加入**（中途进来的人从 0 岁起跑，和已经在跑的人对不上），要等下一局
- 仅桌面端：`pointer: coarse` 或宽度 < 900px 时进房页直接拒绝，多人对战要把每个人画成一列，手机和平板排不下

## 四、推进、暂停、调速与结算规则

**自动推进**：房主 `start` 后，服务端起一个定时器，每 `interval`（默认 1500ms）发一次 `tick`，各端收到就在本地过一年。所以所有人看到的是同一个年份。

**调速**：顶栏有 `慢 / 正常 / 快 / 极速` 四档（3000 / 1500 / 800 / 400 毫秒每年），**任何一个人点一下就全房间变速**，不分房主。改节拍只需重开定时器（`setInterval` 的周期是创建时定死的），下一拍就按新速度走。档位定义在 `protocol.ts` 的 `SPEEDS`，加档位不用改协议。

**开局先等人**：`start` 之后房间是暂停状态，等所有人**进入对局**（各自选完天赋、分配完属性，发出第一条 `sync`）才开始走。否则先选完的人会在别人还在选天赋的时候白跑好几年。最长等 `ENTER_TIMEOUT`（默认 60 秒），到点强制开跑，防止一个人卡在选天赋页面。

**暂停 / 继续**：任何一个人按暂停，全房间停下；**任何一个人**再按继续，就接着跑。没有权限控制，这是唯一不会把人卡死的规则。界面会显示是谁按的。

**阵亡**：生命归零后不再推进自己那一列，页面转观战；掉线按阵亡处理但**保留在榜单上**，否则排名会凭空少一个人。

**结算**：**全员阵亡才结算**，按年龄降序、同年龄按总评降序。注意这里比的是"谁走得远"，不是"谁活到最后"——人人都有一死，所以不能写成"只剩一人就结束"。

**一结束就回房间**：结算没有停留和倒计时。服务端算完名次，当场把房间放回 `lobby`：年龄 / 日志 / 阵亡标记全部清零，**掉线的人顺手清出房间**（不给幽灵留位置），房主还在就继续当；名次挂在 `room.result` 上一起下发。客户端看到 `phase` 变回 `lobby` 就退回房间页 —— 房间页顶部显示「上一局排名」（自己那行高亮），房主随时可以开下一局，开局时 `result` 被清空。想离开的人点「离开」回首页。

**兜底**：`packages/data/BUGS.md` 记录的"400 岁复活后抽不到事件"会导致 `next()` 抛错，多人局里会炸掉整个房间，所以推进时包了 try/catch，失败按阵亡处理。

## 五、明确不做的三件事

这几条是刻意留白的，不是遗漏：

1. **不做存档公平性**。现在每个人用自己浏览器里的 `profile`，老玩家的成就解锁状态会影响成就触发点，严格说不公平。当前接受这个偏差，不统一成空白存档。
2. **不做断线重连**。断了就按阵亡算，重连会被当成新玩家。当前状态下刷新页面即退出对局。
3. **不做房间列表 / 排行榜**。房间只靠链接分享，没有大厅、没有历史战绩。

## 六、界面：整屏 N 列

开局后进入 `containers/Battle.tsx`，一屏之内每人一列：

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ABCD  已过 12 年  4/4 人在跑  速度[慢|正常|快|极速]  [暂停][复制邀请][退出] │
│ ⏸ 小明 暂停了对局，任何一个人都可以点「继续」                              │
├──────────────┬──────────────┬──────────────┬────────────────────────────┤
│ 我（高亮边）  │ 对手 A        │ 对手 B        │ 对手 C                      │
│ 属性条       │ 属性条        │ 属性条        │ 属性条                      │
│ 完整日志     │ 同款日志      │ 同款日志      │ 同款日志                    │
│ 自动推进中…  │ 自动推进中…   │ 已结束        │ 已结束                      │
└──────────────┴──────────────┴──────────────┴────────────────────────────┘
```

- **自己那一列**是完整的本地游戏：属性有涨跌动画，日志自动跟随最新一年
- **别人那一列**是服务端广播过来的镜像：同一套 `components/LogList.tsx` 渲染，所以看起来和自己的人生完全一致，只是不能点
- 顶栏显示房间号、已过年数、存活人数、**速度四档**（选中的高亮，任何一个人都能换档），以及**暂停 / 继续**按钮；暂停时下面多一条蓝色提示条说明是谁停的
- 顶栏下面是**弹幕区**（最多三行留言，像聊天一样往上长），页面最下方是**弹幕输入框**（回车发送，详见第十节）
- 没有结算浮层：最后一个人阵亡的那一拍，界面直接回到房间页，排名以「上一局排名」的形式挂在房间页顶部
- 布局按人数自动排：1–3 人单行等分，**4 人 2 × 2**（比一字排开每列宽一倍），5–6 人 3 列，7–8 人 4 列

| 人数 | 布局 | 1920 屏每列宽度 | 结论 |
|---|---|---|---|
| 2 | 二等分 | ~940px | 很宽裕 |
| 3 | 三等分 | ~620px | 舒适 |
| 4 | 2 × 2 | ~940 × 2 行 | 和单人宽度接近，日志读得清 |
| 4 | 一字排开（未采用） | ~460px | 字会挤，所以没做成选项 |
| 5–8 | 3–4 列换行 | ~450–620px | 能跑，越往下越像排行榜 |

## 七、本地开发与验证

```bash
pnpm dev:server   # ws://localhost:8787
pnpm dev          # http://localhost:5173
```

开两个标签页访问 `http://localhost:5173/?room=TEST1`，房主点「开始对局」，各自选天赋、分配属性，进入对战页后**什么都不用点**，会自动一年一年往下走；想停下来细看就按「暂停」，觉得无聊就点「极速」，一局结束会当场回到房间页（顶上显示上一局排名），房主直接再点「开始对局」就是下一局。

前端连哪个地址由 `apps/web/src/multi/client.ts` 的 `resolveUrl()` 决定，优先级：

1. `?ws=wss://...` 查询参数（测试时最方便）
2. `VITE_WS_URL` 环境变量
3. 同域 `/ws`（https）/ `:8787`（http）

两个自动化验证（都自己起临时中继、`ROUND_MS=150`，不依赖手动开服务，也不是 mock）：


## 八、上线（liferestart.jopatk.top）

**1. 构建服务端**

```bash
pnpm --filter @remake/server build   # 产出 apps/server/dist/index.js，Node 可直跑
```

服务器（47.99.207.128，杭州，2C/1.6G）上放到 `/root/opt/remake-multi/`，照抄 `bomberman-server.service` 写一个 systemd 单元，监听 8787。可调的环境变量：`ROUND_MS`（初始节拍，默认 1500）、`RESULT_MS`（结算浮层停留，默认 15000）、`ENTER_TIMEOUT`（等人进入的上限，默认 60000）。

**2. nginx**

```nginx
server {
    server_name liferestart.jopatk.top;

    location / {
        root /root/opt/remake-web;    # pnpm build:web 的产物
        try_files $uri $uri/ /index.html;
    }

    location /ws {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;     # 一行人生能跑很久，别 60s 断开
    }
}
```

`proxy_read_timeout` 必须调大，默认 60 秒会把人踢下线；服务端自己有 30 秒心跳清理假死连接，两边配合正好。

**3. B 站 Toy**

静态包上传到 Toy，`wss://liferestart.jopatk.top/ws` 连杭州服务器即可，和炸弹人走的是同一条路。

## 九、已知限制

- **刷新页面 = 退出对局**（不做重连，见第五节），会被按阵亡处理并留在榜单上
- **节拍是房间级的**：任何人改都会影响全场，不能各人各速（想要各速就得给每个人单独计时，年份就对不齐了）
- **观察不到更早的历史**：对手列只有最近 18 年，再往前的日志不会同步
- **中途加入被拒**：开局后点邀请链接进来会提示"对局已经开始"，得等房主重开一局
- **排名只在房间里**：打完立刻回房间，上一局排名挂在房间页顶部，开局后就被清掉；想留档只能自己截图（没有历史战绩，见第五节）
- **别人的最后一屏看不到**：全员阵亡的那一拍直接回房间，最后一年对手刚滚出来的日志也就跟着收走了
- **弹幕不留档**：服务端只转发不存，刷新 / 晚进来都看不到之前的弹幕；屏幕上只留最后 3 条，更早的会被顶掉，也没有屏蔽开关

## 十、弹幕

多人局的乐趣有一半在互相吐槽，但这一屏最重要的是四个人的人生日志，**弹幕不能压住日志**，所以不做全屏飘字，做顶栏下方几行常驻留言。

关键行为：**不飞、也不定时消失**。新的一条从下面顶上来，一直留在那儿，只有攒满三行、位置不够了，最上面那条才被挤出去 —— 更接近群聊，而不是一闪过就没的弹幕。

```
┌──────────────────────────────────────────────────────────────┐
│ OVER  已过 12 年  1/1 人  速度[慢|正常|快|极速]  [暂停][邀请]  │
├──────────────────────────────────────────────────────────────┤
│ 【小明】：这波家境的骰子太黑了                 ← 攒满三行时，被下一条顶掉 │
│ 【阿花】：笑死，又活到 3 岁                                    │
│ 【我】：我这次要活到 90                        ← 最新，贴着下面往上长   │
├──────────────┬──────────────┬──────────────┬─────────────────┤
│ …人生日志…    │               │               │                 │
├──────────────┴───────────────┴───────────────┴─────────────────┤
│ [ 说点什么，回车发送                                    ] [发送] │
└──────────────────────────────────────────────────────────────┘
```

**协议**（服务端仍然不碰游戏逻辑，只补名字并转发）：

| 方向 | 消息 | 说明 |
|---|---|---|
| C→S | `danmaku { text }` | 发送，文本由服务端净化、截断、限流 |
| S→C | `danmaku { id, from, name, text, at }` | 全房间广播（发的人自己也收到一份），`from` 是发送者玩家 id |

**规则**

- 文本 ≤ 40 字，去掉换行和首尾空白；空串直接丢弃
- 每个连接 1.5 秒最多 1 条，超了丢弃并回一条 `error`（「发得有点快，缓一下再发」），不排队；客户端也按同样间隔把发送按钮置灰，正常手速撞不到
- **屏幕只留最后 3 条**：新的从下面追加，满了就把最上面那条顶掉。除此之外没有任何清理逻辑 —— 不再有 TTL，也不会左右飞走
- 本地最多记 6 条（`DANMAKU_KEEP`），画面上只渲染 3 条；多留几条是为了从对战页退回房间页时，最近的对话还在
- **服务端不存历史**：只转发，刷新 / 晚进来都看不到之前的弹幕
- 暂停时照样能发 —— 暂停本来就是大家说话的时候
- 房间页（等开局、结算后）也能发，用的是同一个组件
- React 默认转义，不解析 HTML / 链接 / 表情指令

**改动点**

1. `packages/multi/src/protocol.ts`：`danmaku` 两个方向的消息 + `DANMAKU_LIMIT = 40`、`DANMAKU_GAP = 1500`、`DANMAKU_KEEP = 6`
2. `apps/server/src/room.ts`：`danmaku(id, text)` —— 净化、限流（`danmakuAt` 记录每人上次发送时间）、广播；房间回收时一起清掉
3. `apps/web/src/components/Danmaku.tsx`：`DanmakuTrack`（画最后 3 条，静态堆叠，新的一条淡入）+ `DanmakuInput`（底部常驻输入框），`Battle.tsx` 与 `Room.tsx` 各放一份
4. `apps/web/src/multi/client.ts`：`sendDanmaku()`，收到后追加并裁到 `DANMAKU_KEEP`，没有定时器
5. `apps/server/test/protocol.ts`：广播给所有人、名字由服务端补、去空白、连发限流、超长截断

**明确不做的**：不做私聊、不做自定义颜色 / 字号、不做弹幕屏蔽开关；服务端不存聊天记录，刷新就没了（要留档得自己做）。
